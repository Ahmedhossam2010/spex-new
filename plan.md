# SPEX transformation plan

## Implementation approach

Preserve the Express/Vite and real science pipeline. Add the educational experience as a separate client feature module and route it through the existing App/Header shell. Improve global styling with CSS tokens and responsive rules rather than rewriting the Explore science renderer. Repair candidate coordinate quantization and conservative motion classification in the pipeline, then document verified limitations and release-day handling.

## Project structure

- `src/App.tsx`: global navigation, theme, language, real investigation state.
- `src/components/`: product views, scientific workspace, mascot, and `MissionGame`.
- `src/education/`: synthetic educational content only.
- `src/science/`: FITS, WCS, pipeline, catalog, release adapter, and regression tests.
- `src/utils/`: rendering, glossary, and translations.
- `docs/`: architecture, integrity, design, education, QA, and release documentation.

## Design movement

1. Mission-control editorial / 0.06 probability. 2. Quiet observatory instrument / 0.91 probability. 3. Retro-futurist arcade / 0.03 probability.

Chosen: **Quiet observatory instrument**. It uses deep midnight surfaces, warm measurement amber, cyan observation cues, restrained violet learning cues, asymmetric editorial spacing, monospaced telemetry, and animation only when it clarifies a scientific transition. SPEX is a guide, not a generic chatbot; the brand voice is curious, grounded, and honest: “Look closer.” and “A difference is a question, not a conclusion.”

## Outcome list

- Preserve the real FITS/WCS/difference/provenance path.
- Add subpixel candidate centroid fields with an uncertainty fallback.
- Prevent weak/artifact-like opposite residuals from being promoted to moving-object candidates.
- Add Learn navigation and a two-level synthetic educational mission.
- Make synthetic-data labeling visible and isolate educational data from the science engine.
- Add responsive/reduced-motion/focus styles and route manifest.
- Publish honest architecture, integrity, QA, education, and release-readiness documentation.
